Project Overview

MCA WALLAH Portfolio & Dynamic CMS is an advanced, production-grade developer portfolio website tightly integrated with a secure, full-scale administrative Content Management System (CMS). Unlike conventional static portfolio sites that require developers to manually edit JSX/HTML code, push commits, and redeploy every time a project, skill, resume, or contact link changes, this system decouples content and presentation logic through an intuitive visual administration studio.

The platform is designed to serve two primary audiences: (1) Public Visitors & Recruiters, who experience a fast, responsive, glassmorphic portfolio equipped with real-time interactive themes, multi-resume downloads, contact dispatching, and an embedded arcade lounge; and (2) The Portfolio Owner / Admin, who maintains complete programmatic control over every single visual component, section order, layout variant, database asset, and live telemetry log without writing a single line of backend code.

03

Problem Statement

In modern software engineering recruitment and freelance markets, static single-page portfolios suffer from major technical and operational bottlenecks:

  • High Maintenance Friction: Updating resume versions, project descriptions, live deployment links, or skill proficiencies requires source code modification, recompilation, and production deployment cycles.
  • Single-Resume Rigidity: Standard portfolios provide only a single generic resume link. Recruiters targeting specialized roles (e.g., Full Stack Engineer vs. UI/UX Designer vs. Python Specialist) require role-tailored resumes.
  • Zero Interaction Observability: Developers typically have no insight into who downloaded their resume, which projects generated clicks, or how visitors engaged with the site beyond generic third-party analytics scripts.
  • Monolithic Aesthetics: Traditional portfolios lock the user into a single layout and color palette, preventing personalization or dynamic theme adaptation.

The MCA WALLAH system resolves these challenges by implementing a dynamic, database-driven architecture featuring an administrative CRUD studio, multi-resume vault management, custom background styling engine, telemetry logging, and interactive visitor engagement modules.

Application Workflow

Visitor Interaction Flow

  1. Initial Hydration: Client requests root route /. DataContext executes a single unified query to GET /api/portfolio/public.
  2. Dynamic Rendering: React renders all sections using retrieved CMS document settings.
  3. Live Customization: Visitor uses the draggable floating background widget to adjust visual themes locally in state.
  4. Resume Interaction: Visitor downloads or previews resumes from the dynamic dropdown populated from the Resume Vault.
  5. Engagement & Gaming: Playing arcade games triggers score recording via POST /api/portfolio/games/:slug/score.
  6. Contact Submission: Sending a message passes through client validation and rate-limited dispatch.

Admin Studio Workflow

  1. Authentication: Admin logs in via /admin/login against POST /api/auth/login.
  2. Token Verification: Server issues an Access Token stored in localStorage.
  3. Live Editing: Admin modifies content and saves via PUT/POST to /api/admin/section/:type.
  4. Instant Propagation: Frontend broadcasts through BroadcastChannel('portfolio_updates'), updating public tabs instantly.

Backend Architecture & Controllers

The backend is structured around Express REST controllers, Mongoose data models, and specialized security middleware:

  • portfolioController.js: Handles public aggregated queries (getPublicPortfolio), contact message submission with Nodemailer dispatch, newsletter subscription, and game leaderboard submission/retrieval.
  • adminController.js: Provides complete administrative CRUD operations across all portfolio sections, user directory management, status toggles, activity log inspection, and JSON backup/restore.
  • authController.js: Implements secure user registration, BCrypt password validation, JWT access and refresh token generation, user preference updates, and avatar uploads.
  • mediaController.js: Handles multipart asset uploads via Multer, routing to Cloudinary when configured or falling back to local disk storage.

Database Architecture (MongoDB Schemas)

The database layer is implemented on MongoDB using Mongoose 8. The database utilizes 16 specialized schema collections with indexed fields for high-throughput queries:

User Schema (users)
  • name (String, required)
  • email (String, required, unique, indexed)
  • password (String, hashed via bcrypt)
  • role (Enum: 'admin' | 'editor' | 'user')
  • preferences (darkMode, background, accentColor)
  • lastLogin, loginCount, lastIp, device
  • isSuspended (Boolean, default false)
GameScore Schema (gamescores)
  • gameSlug (Enum: 'snake' | '2048' | 'typing' | 'tictactoe')
  • playerName (String, default 'Player')
  • score (Number, required, indexed)
  • metrics (wpm, accuracy, highestTile, moves)
  • userId (ObjectId, ref: 'User')
  • Compound Index: { gameSlug: 1, score: -1 }
Hero Schema (heroes)
  • layoutStyle (Enum: 'glassmorphism' | 'split' | 'editorial' | 'hologram')
  • typewriterRoles (Array of Strings)
  • techPills (Array of Strings)
  • stats (Array of { value, label })
  • socialLinks (Array of { label, href, icon })
About Schema & Vault (abouts)
  • displayName, title, location, avatarUrl
  • paragraphs (Array of Strings)
  • quickStats, hobbies
  • resumes (Array of { title, url, fileName, fileSize, isVisible, isDefault })

Authentication & Security Mechanisms

Security Architecture Summary

The system enforces a multi-layered security perimeter incorporating stateful cryptographic hashing, stateless JWT authorization, and defensive request throttling.

  • Password Cryptography: Passwords are never stored in plaintext. Mongoose pre-save hooks automatically hash passwords with BCrypt using 10 salt rounds.
  • Dual-Token Authorization: Upon successful login, the server issues a 7-day signed Access Token (JWT_SECRET) and a 30-day Refresh Token (JWT_REFRESH_SECRET).
  • Role-Based Access Control (RBAC): The protectAdmin middleware verifies token signature and confirms user.role === 'admin' before allowing access to administrative mutation routes.
  • Spam Throttling: The public contact form is protected by express-rate-limit, restricting clients to 5 message submissions per 10-minute window per IP.
  • File Upload Sanitization: Multer enforces strict MIME-type allowlists (PDF, DOC, DOCX, JPEG, PNG, WEBP, SVG) and an upper file boundary of 10MB.

Performance Optimization

  • Single Aggregated Network Request: All portfolio content is loaded in a single aggregated GET /api/portfolio/public query.
  • Compound Database Indexing: Mongoose models use compound indices for sub-millisecond query responses.
  • Zero-Dependency Styling: Clean Vanilla CSS design tokens without heavyweight styling framework overhead.
22

System Limitations

  • Single Primary Administrator Model: Granular role-based permissions for editors are not yet fully differentiated.
  • Synchronous Nodemailer Dispatch: Email notifications are processed synchronously.
  • Local Upload Fallback Dependency: Relies on local disk storage when Cloudinary credentials are not configured.
